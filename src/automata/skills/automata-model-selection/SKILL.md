# Automata Model Selection

Recommend models suited to the work using a small comparative guide, not a fixed
routing table. Continuing unchanged authorized work needs no new selection exercise.

1. **Choose for the task.** Consult relevant guidance and approved preferences.
   Compare viable options by reasoning, context, tool use and verification needs;
   include briefing, review and correction costs. Give the recommendation and main
   tradeoff. Research only uncertainty that could change the choice; otherwise
   state limits without blocking work. Planning without a model or assignee choice
   does not itself require selection.

2. **Check evidence and availability.** Prefer primary sources for identity and
   features, relevant independent results for performance. Separate vendor claims,
   observations and hypotheses; compare task, harness and effort before transferring
   results. Identify provider/version and label moving aliases or unknown mappings.
   Recheck affected claims after meaningful changes or conflicting evidence, not
   age alone. Publication, documentation verification and trial dates are distinct;
   update only what was checked. Public availability is not runtime access.

3. **Resolve effort before launch.** Choose supported model/effort settings and verify
   effective values; runtimes may clamp requests. Do not assume an agent-callable
   dynamic setter. Per-operation effort, such as compaction-summary effort, does
   not change the working session. Recommendations do not authorize settings changes.

4. **Maintain a compact guide.** Record choose-when, main tradeoff and evidence/
   freshness with a few references. Label tentative advice and setup differences;
   update existing entries instead of accumulating research dumps. Read before
   updating, and keep records outside the package within authorized storage:
   - Global: `~/.agents/var/skills/automata-model-selection/selection-guide.md`;
     approved choices in `preferences.md` beside it.
   - Project observations/overrides: corresponding project `.agents/var/skills/`
     paths. Keep private evidence local unless broader sharing is authorized.

5. **Respect preference scope.** Confirm meaningful preference changes before saving;
   research changes advice, not permission. Record user choices, scope and confirmation
   date; distinguish allowed sets from favorites. Absence is neither a ban nor
   permission. Apply current scoped instructions, then explicit project overrides,
   then global preferences. Resolve conflicts; do not relax prohibitions through
   ambiguity or turn task exceptions into global rules. Saved guidance is neither
   configuration nor proof of access, and authorizes no paid trials, agents,
   private-data transfers, installation or monitoring.

This skill owns model advice and preferences. Work planning, assignment design and
runtime availability retain their own responsibilities.
